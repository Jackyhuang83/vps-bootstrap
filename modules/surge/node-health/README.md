# Surge 节点体检 · v0.1.0-beta.20

选定已有策略组后，在组内选哪个节点就检测哪个。默认面板参考网络信息 𝕏、Stream-All 和 IPPure 的紧凑布局：IP 信息几行、平台一项一行、广州三网各一行。详细诊断可直接在 Surge 原生「检测详情」面板读取，无需打开网页。

**当前为测试版，真实 Surge、所选节点路径及手机界面尚未实机验收。** 广州目录、会话握手和响应头流程已在执行环境完成真实网络请求；该结果不代表每个用户节点均可到达。

## 安装与使用

Surge → 模块 → 从 URL 安装：

```text
https://raw.githubusercontent.com/Jackyhuang83/vps-bootstrap/feat/surge-node-health/modules/surge/node-health/node-health.sgmodule
```

1. 保持默认参数启用模块，点击「检测设置」面板。每点一次切到下一个已有手动选择组，立即保存；选到平时切节点的那一组即可停下。
2. 在该组中选择节点，分别刷新「IP 纯净度」「平台解锁检测」「广州三网延迟」「入口落地查询」。入口落地是独立面板，紧接广州三网下面；每次固定所选具体节点，不批量扫描其他节点。
3. 下次检测同组里的其他节点，只需切节点、刷新检测面板。重新进入策略页只更新设置文字，不自动切组。
4. 查看诊断时，点按最下方「检测详情」面板，显示最近一次检测的记录；继续点按翻页，末页再次点按收起。要看广州三网的失败原因，先刷新广州三网，再点按检测详情。
5. 要复制记录，保持 Surge 与模块启用，在 Safari 打开 `http://192.0.2.1/copy`，点击「复制全文」。这里复制完整记录，不限于原生面板当前页；也可点「选中全文」后长按复制，或打开 `http://192.0.2.1/reports.txt` 查看纯文本。

不需要通知权限、输入组名、MITM、证书或 HTTP API 监听端口。IP 纯净度面板直接显示完整出口 IP，不再需要 SHOW_IP 开关；旧版 showIP=false 参数仍可读取，但不会隐藏面板地址。保存的详细记录仍会打码。

已有旧版时，用同一安装地址更新模块；脚本 URL 和「检测设置」面板应显示 `v0.1.0-beta.20`。四个检测面板只显示更新时间，详情保留记录生成时的版本。必须更新模块定义才会添加新的详情入口及数字地址拦截；仅刷新旧面板不会添加它们。旧缓存的生成版本不会随模块更新自动变化。Beta 1/2 的旧 `policy` 参数仍可读，本机保存的组优先。

需要当前 Surge 的脚本能力。外部订阅节点标识依赖官方标注的 iOS 5.24.0+ / Mac 6.11.0+；旧版无法识别时会提示，不回退直连。嵌套手动组可解析；自动测速、故障转移或负载均衡子组无法固定到具体节点时，会要求改选具体节点。

## 默认面板

- **IP 纯净度**：先显示出口、国旗/位置、ASN 公司；空行后显示 IP 属性和风险分。只显示 IPPure 风险分及等级，分数越低风险越低；不同时堆叠反向计算的纯净度分。出口不同、单来源有效或地区库有差异才增加提示，完整交叉核对保留在详情。图标颜色反映评分状态。
- **平台解锁检测**：ChatGPT、Gemini、Claude、Google 为第一段；Netflix、Disney+、YouTube Premium、myTV SUPER、TikTok 为第二段。每项按「平台：短结论 · 地区」显示，两段间留一行空白。明确国家代码加国旗，常见三字代码（如 JPN）规范为 JP；未识别地区保留原值，不猜测国旗。ChatGPT 的 Cloudflare 地区明确标注「边缘」，不当作服务授权地区。Google 页脚地区保留原始名称，不从节点位置补齐。
- **广州三网延迟**：广州电信、广州联通、广州移动各一行，显示有效样本的中位耗时。部分成功标注有效次数；目录缺少目标时显示「未取得广州测点」；已请求测点但失败时显示实际连接错误或超时。
- **入口落地查询**：独立放在广州三网下面，分公网 IP（直连）、入口 IP、落地 IP 三段，取得地址时显示完整 IP、地理库位置和 ASN 公司。节点及本次更新时间保留在底部。
- **检测设置**：选定后为四行：策略组、当前节点、点按切组/组序号/版本，以及可选网页选组地址。不显示常规提示图标，读取或保存失败时保留警示样式。
- **检测详情**：位于入口落地下面。默认短摘要显示最新记录的类别、时间、版本和复制地址；点按展开，每页最多 700 个 Unicode 字符，继续点按翻页、末页收起。新检测记录生成后回到摘要，避免把旧页误当作新结果。原生阅读不发起检测、不读取或修改策略组，也不依赖浏览器、HTTP 拦截、通知或 API 监听。面板自身不支持网页按钮，复制通过下述本地页面完成。

平台和三网结果直接显示文字结论或耗时，不使用状态表情符号。网页可达、地区检查、样本片库可见均不等于账号权益、DRM、实际播放或对话通过。

四个检测面板统一为结果、空行、节点、时间/检测范围，先看结论，底部核对本次检测的节点。短结论区分「地区支持」「网页可达」「授权样本可见」「地区受限」「需要验证」「检测超时」等，不把有限证据统称为完整支持。完整原因、Netflix 有效样本次数仍在详情保留。

不使用空格强行对齐不同长度的名称，不增加状态表情或长横线。不展示接口列表、HTTP 状态、API 认证正文、样本编号、逐次耗时或诊断段落；这些内容在详情页查看。每张卡片保留上次刷新结果，切节点后需分别刷新并核对节点和时间。原生 Panel 使用官方文字与图标接口，不承诺逐项加粗或单独着色。

## 阅读与复制检测详情

优先使用最下方的「检测详情」面板。先刷新要排查的检测项目，再点按详情查看刚才的记录；HTTP 状态、主机、来源、耗时和失败原因均保留。长内容可分页读取，展开状态下重新进入策略页不会自动翻页；新记录生成后重新点按从第一页查看。只读取现有本机记录，IP 保持打码。

复制时在 Safari 打开 **`http://192.0.2.1/copy`**，保留 `http://`。这是模块接管的数字地址，绕过 `.invalid` 域名解析；仅为 `192.0.2.1/32` 添加 VIF 包含路由，并为该地址及原本的域名在 80 端口指定 HTTP 引擎处理、排除强制原始 TCP，不开监听端口、不添加 MITM。更新模块定义后才生效，不能仅更新脚本。它仍需要浏览器请求经过 Surge，尚未完成真实手机入口验收。

页面直接返回本机最近一份记录，文本随 HTML 安全转义嵌入，无需再请求 `/api/reports` 才显示。点击「复制全文」后，仅在剪贴板接口成功或浏览器复制命令返回成功时显示“已复制”。浏览器不支持或拒绝自动复制时，保留选中的文本框并提示长按复制；「选中全文」可独立使用。`/reports.txt` 是完整纯文本备用入口，`/reports` 保留四类缓存记录。复制内容包含生成时的类别、时间、版本和全部详情，IP 保持打码；刷新网页只读缓存，不重新检测或上传记录。

数字地址只提供读取/复制，不开放策略组列表或组绑定写入；原有域名上的网页选组仍校验来源、请求头和现有组。记录不放进 URL 参数，也不通过公共网页分享服务传输。

以下网页仍作为可选入口，用于点选策略组或同时查看四种缓存记录。它不是公网网站：浏览器请求必须经过本机 Surge HTTP 引擎才会被脚本接管；其他浏览器、内嵌浏览器或 HTTPS 请求可能无法打开。网页失败时直接使用原生面板，不需要为此开启 MITM、安装证书或开放端口。

保持 Surge 和模块启用，在 Safari 打开：

```text
http://surge-node-health.invalid/
```

页面上方可切换「选检测组」「检测详情」。网页组列表点一下即保存，与设置面板共用同一绑定；策略组多时可以直接点选。Safari 分享 → 添加到主屏幕，可保存「节点体检设置」入口。

网页详情按四张检测卡片保存最近一次结果，显示各自节点、时间和版本。刷新记录只读取本机缓存，不发起检测。四张卡片可能来自不同节点或不同时刻，核对后再比较；保存的公网、入口和落地地址均打码。原生详情仅显示其中时间最新的一份，翻页位置单独保存，不改动检测记录与组绑定。

记录只保存在本机 Surge 脚本存储中，出口 IP 始终打码，不保存原始响应、用户 Cookie/Key 或 CDN 临时 URL 参数。名称和记录均按纯文本展示。设置写入校验来源、请求头及现有组列表；读取响应禁用缓存，不开放 CORS。

保留地址的 `http://`。这是 HTTP 请求脚本返回的本地页面，模块为保留域名添加文档地址 Host 映射，正常启用时不会请求真实外部站点。若打不开，核对脚本是否已下载、Surge/模块是否启用，以及浏览器是否改成 HTTPS。配置中的绕过项、拒绝项或优先请求脚本也可能阻止本地拦截。无需开放端口。

## IP 与平台检测依据

IPPure、IP.SB GeoIP 和 Cloudflare Trace 并行读取自身出口。至少两个来源有效时核对 IP，IPv6 先规范化；不同 IP 和同 IP 的地区库差异分别提示。IPPure 失败时仍可显示备用来源信息，风险分保持未知。

面板显示 IPPure 风险分（越低越好）；详情仍保留 `100 − IPPure 风险分` 的参考值，不是安全概率。只接受 0–100 有限数值；缺失、异常、限流和 HTML 不评分。IPPure 不评估 IPv6，IPv6 不生成纯净度分。住宅、机房、广播字段独立处理，不推断原生属性。各来源可能连接不同地址族，不据此宣称双栈均已检测。

| 平台 | 详情保留的检测证据 |
| --- | --- |
| ChatGPT | Web、iOS App 入口、OpenAI API 模型入口、ChatGPT 边缘 Trace；边缘地区明确标注，不当作服务授权地区 |
| Gemini | 自身网页地区/功能标志、Gemini API 模型入口；标志缺失不判地区不支持 |
| Claude | Web、明确地区拒绝页/跳转、Claude API 模型入口 |
| Google | 一次小型搜索的结果列表、验证码及可识别的页脚地区，不强制国家参数 |
| Netflix | 两个区域样本 81280792/70143836、自制样本 80018499；Fast.com 分配 CDN 后对 HTTPS *.nflxvideo.net 发一次 HEAD |

## 入口与落地的范围

- **公网 IP（直连）**：只有这个区块显式使用 DIRECT，实测当前网络访问探测站的公网出口；不是手机 LAN 地址，也不保证代表物理宽带归属（其他系统隧道仍可能影响出口）。
- **落地 IP**：通过已固定的所选节点访问探测站；不因失败改成 DIRECT。两个区块各用独立的本次标识，Cloudflare trace 为首选，失败后使用 IP.SB 备用；每个请求 4 秒。
- **入口 IP**：探测完成后只读 Surge 的最近请求，严格匹配本次节点探测的唯一 URL、所选具体节点身份和 remoteAddress 的 `(Proxy)` 标记。只取连接记录中的 IP，不把探测站地址、旧记录或域名 DNS 结果当作入口；IPv4 端口和括号 IPv6 可解析。多个不同地址显示待确认，保留打码后的详情；记录不可读、缺失或格式变化时只将入口标为未取得。
- **位置与公司**：按明确 IP 查询 IP.SB，核对响应 IP 一致才采用地理资料；相同地址只查一次。缺失字段可使用 Surge 本地国家/ASN/组织库，缺失城市不猜测。私有入口不提交外部查询。所有地理资料均为数据库归属参考，不代表机房物理地址。

不需要 VPS 程序、HTTP API 监听、MITM 或通知，也不开启抓包。仅在本地处理匹配到的探测记录，不保存其他请求、请求头、Cookie 或原始 API 响应。记录格式与在线接口仍需真实 Surge 验收。此功能不还原服务商隐藏转发，不根据入口/落地差异推断中转跳数，也不解析客户端配置链。

## Beta 20：一次性兼容测试与诊断

部分真实 Surge 节点对广州三网测速站的握手 GET 成功，而预检 HEAD 连接失败。上游 better-speedtest 用 TCP 建连测试延迟、用 GET 进行下载，未承诺 1GB 文件接口支持 HEAD。此时不能断言该测点不可达。

新逻辑先执行既有 HEAD 预检。若通过，保持三次 HEAD 正式采样。若失败，直接在相同选中节点和广州测点上，发送三次独立的 GET /speed/dovalid 小体积会话请求（每次随机公开协议标识与重新签名），仅接受 HTTP 200 以及有效 1-UUID 会话响应。严格拒绝 HTML、403、超时及格式不符。两种采样不混合；回退采样的面板数值标记“HTTP 会话”，包含服务端处理时间，不是 TCP Ping / RTT，不能和 HEAD 数值直接比较。

**绝不 GET /speed/File(1G).dl，不下载测速文件正文。** 仍固定单一已选节点，不会切换 DIRECT；保留失败阶段、n/3、样本波动、时限、隐私脱敏与候选回退。手机真机端是否已成功仍待验收。

## Beta 19：握手失败时的传输对照

本版是针对实际 Surge 中“三网握手连接失败、普通 HTTPS 可达”的**诊断增强**，不是已修复声明。若握手在网络层失败，将对同一节点、同一广州 IP 与端口额外发送一次无会话的 HEAD（不下载文件正文）。收到任何 HTTP 状态，包括 403，说明该端口上的 HTTP 至少有响应；没有响应只能归类为“同端口 HTTP 未响应”，不能证明是服务端宕机还是链路过滤。协议握手失败不转成延迟样本。

三网均为网络错误时，除原有 HTTPS 443 对照，再使用同一节点执行一次 HTTP 80 对照。两者与三网检测分开呈现，不计入广州延迟。若 HTTP 80 和 HTTPS 443 可达而三网同端口均无响应，应优先排查出口对非标准端口的可达性；若 80 同样失败，则要考虑明文 HTTP 处理/链路限制。此处不执行 TCP SYN/ICMP、不自动回退 DIRECT、也不引入虚假的三网 RTT。新增请求最多三次同端口 HEAD 和一次 HTTP 80 对照，均有独立超时。

## 广州三网的测量范围

采用“目录发现 → 会话握手 → HEAD 预检 → 三次采样”的流程；HEAD 预检失败时自动使用三次独立的小体积 GET 会话采样。测点来自全球网测的公开目录，握手流程参考 `better-speedtest` 的客户端实现；预热剔除的思路参考 `speedtest-go` 的 HTTP 模式。这里使用 HTTP HEAD 或会话握手往返；**不声称实现 Ookla 原生 TCP/UDP 协议或与 Speedtest App 数值相同**。

三网目录请求并行，全部固定当前选中的具体节点；只接受省份广东、城市广州/广州市、名称严格对应广州电信/联通/移动、公网 IPv4、规定端口和数字 ID。其他城市、内网地址、混合运营商或任意主机 URL 不采用。齐全目录元数据缓存 30 分钟，切换节点时优先相同测点；不缓存会话标识。目录缺失时，使用 2026-10-17 返回并在执行环境验证过的三个地址：

| 运营商 | 目录 ID | 公网测点 | 目录声明 |
| --- | --- | --- | --- |
| 电信 | 1101 | `61.144.6.18:65499` | 广东 · 广州电信 |
| 联通 | 1102 | `218.107.8.18:65499` | 广东 · 广州联通 |
| 移动 | 1103 | `183.235.59.38:65499` | 广东 · 广州移动 |

这些地址是测速服务，不是 DNS Ping 目标。目录与快照表示来源声明，不独立证明机房位置，也不保证永久在线；每次必须重新握手和校验响应。已移除此前 Ookla 目录和旧候选依赖。

先按公开协议请求 `/speed/dovalid`，只接受 HTTP 200 与严格的 `1-UUID` 会话响应。握手使用临时随机协议标识，**不读取手机 IMEI、不需要账号或 VPS 程序**。协议签名只针对公开字段，不是用户账号凭据。会话值、临时标识和完整带参数的请求 URL 只在当次运行内使用，不写入模块诊断缓存或日志；Surge 自身流量查看器仍可能显示脚本请求 URL。

带会话参数对 `/speed/File(1G).dl` 发送 **HEAD**，只读响应头，**不 GET 或下载该文件**。只有 HTTP 200 且 `Content-Length` 严格为 `1073741824` 才通过当前服务的响应校验；直接访问文件的 403、通用网页、缺少/错误长度、跳转均不生成延迟。HEAD 是用于轻量检测，不是下载测速。接口使用 HTTP，响应校验不是服务端身份的密码学证明。

节点身份：所选外部订阅组中的节点始终优先使用该组返回的专属 `identifier`；本地同名节点不得抢先匹配。无关外部组也不得覆盖已选本地节点。所有重试、采样与 HTTPS 对照保持同一个已解析节点身份。

连接兼容：握手或首次 HEAD 遇到未知连接错误/连接关闭时，在相同节点、相同 URL 上仅重试一次，显式发送 `Connection: close`，后续该目标也使用独立连接。请求同时声明 `Accept-Encoding: identity`。不对 HTTP 403/429、格式不符、超时、拒绝连接或参数错误进行此兼容重试；正式采样不自动重试，避免隐藏失败或混合耗时。独立连接模式包含各次连接建立开销，不称为纯 RTT。

故障显示：原生行区分握手、预检、采样，并显示可取得的系统错误码。只保留受限的系统错误域/数字码、标准 errno 或 JavaScript 异常类型，丢弃原始错误正文，避免其中的地址、URL、会话参数进入缓存。三网全为网络错误时，额外通过同一所选节点访问一次 Cloudflare HTTPS trace，仅作为连接对照，不计入广州延迟。成功只表示该常规 HTTPS 入口可达；失败也不单凭一次对照认定节点故障。

**真实 Surge 上的三网连接失败根因尚未确认。** 上述改动修正请求兼容与故障定位，不构成高端口或所选节点路径已修复的证明。执行环境的网络适配器会添加连接关闭行为，也经过环境网关，不能等同 Surge 原生请求。

HEAD 预检不计入统计；通过时随后在同一地址、同一会话 HEAD 采样三次，失败时改用三次独立会话 GET，统计有效样本中位数。失败不当作零毫秒；部分有效标明 `1/3` 或 `2/3`，波动只计算相邻均有效样本的差。当前新地址握手/预热失败时，最多尝试一次不同的内置快照地址，两个地址的统计不混用。采样中即保存内存进度，总时限到达时保留已取得的有效样本。

目录每次 6 秒，握手/HEAD 每次 8 秒；三网并行，整体保护 65 秒、模块超时 70 秒。正常完成即返回，不会固定等待 65 秒。各网失败独立，所有请求固定所选节点。

MiniProbe 的 IPv4 默认由 VPS Agent 对运营商 DNS 做 ICMP，另外支持 TCP/UDP 53；Surge 脚本的公开接口不提供对应的原始套接字能力，不能把 DNS 地址直接换成 HTTP URL。这里参考其三网并行、固定目标及失败隔离的设计，保留客户端可执行的 HTTP 方案。

**测量范围仍是手机 → 所选节点 → 广州 HTTP 测点的往返，包含手机到节点及服务器处理时间。** 它不是 VPS 端回程 Ping、逐跳路由、丢包率或 CN2/CMIN2/CUII 等级。MiniProbe 在 VPS 上测得的结果与这里的数值不能直接等同。

## 手机验收

1. 通知保持关闭，切换检测组，重新进入策略页后确认绑定不变。
2. 在同组选择两个出口不同的节点分别刷新 IP，核对节点/IP 跟随，默认卡片是否保持简洁。
3. 平台卡片应每平台一行；在详情页核对 AI/API、样本/CDN 等分项，并用同一节点实际登录、播放或对话对照。
4. 广州卡片应显示三网的耗时或明确失败原因。详情应显示当前目录/快照、会话握手、HEAD 预检及后续三次 HEAD 或 GET 会话采样结果；握手和预热耗时不进入中位数，不能出现会话参数。切换节点比较时核对采用的 ID/主机，失败不等于节点到国内断网。
5. IP 面板应显示完整 IPv4/IPv6，即使沿用旧版 showIP=false 参数；检测详情保留各卡片独立时间和版本，仍对出口打码，刷新记录不发起网络检测。
6. 更新模块后，广州三网下面应出现独立入口落地面板；点击后核对直连公网、入口、落地三个区块。入口未取得时查看本地详情，不把落地 IP 复制成入口；换节点后分别刷新并核对底部节点和时间。
7. 更新模块后，最下方应出现原生「检测详情」。刷新广州三网后点按详情，核对记录类别、节点、时间、请求主机和状态码；翻至末页后再点按应收起。新检测记录生成后应回到摘要。
8. Beta 15 更新模块定义后，在 Safari 打开 `http://192.0.2.1/copy`，点「复制全文」并粘贴到其他 App，核对完整末尾内容而非只有当前原生页。复制被阻止时应保留选中状态、提示长按复制，不虚报成功；纯文本入口应显示同一份完整记录。上述入口不依赖通知。

执行环境已取得三网广州目录，完成真实会话握手及授权 HEAD 200 校验，未读取测速文件正文。模块逻辑另通过网络适配器执行；此验证使用执行环境的出口，不能替代用户 Surge/节点路径。手机面板布局、本地页面拦截及 macOS 仍未实机验证。
